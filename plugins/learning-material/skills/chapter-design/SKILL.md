# 단원 기획서 작성

교재 집필자가 무엇을 어떤 순서로 구성할지 판단할 수 있는 기획서를 만든다. 교재 본문이나 상세 구현 명세를 대신 작성하지 않는다.

## 입력과 템플릿

과정 컨텍스트와 작성 범위는 실행할 때 받는다. 특정 과정의 기술 스택, 시수, 장비, 운영 방식, 디렉터리 구조를 기본값으로 가정하지 않는다. 작업 프로젝트에 지침과 기존 합의가 있으면 해당 범위에 적용한다.

단원 유형에 맞는 스킬 내부 템플릿을 읽는다. 사용자가 템플릿을 갱신했다고 알리면 최신 파일을 다시 읽고 적용한다. 경로는 현재 작업 디렉터리가 아니라 이 SKILL.md의 위치를 기준으로 해석한다.

- [이론 템플릿](assets/template_단원_기획_이론.md)
- [미션 템플릿](assets/template_단원_기획_미션.md)
- [프로젝트 템플릿](assets/template_단원_기획_프로젝트.md)

`assets/`는 형식의 기준이며 결과물 저장 위치가 아니다. 템플릿 원본을 수정하지 않고 사용자가 지정한 경로에 기획서를 저장한다.

## 작성 수준과 문체

- 쉬운 용어와 짧은 문장으로 간단하게 쓴다. 기술 용어는 억지로 번역하지 않는다.
- AI처럼 보편적인 약어는 그대로 쓴다. 흔하지 않은 약어는 각 기획서의 첫 등장에만 `약어(Full Spelling)`로 쓴다.
- 새 마크다운에는 미들닷(U+00B7)을 사용하지 않는다.
- 템플릿의 섹션과 항목을 유지하되, 인용문으로 된 도움 설명, 작성 예시, 빈 항목과 자리표시자는 결과물에서 제거한다. 해당 사항이 없는 섹션은 짧게 그 상태를 밝힌다. 단, 내러티브 관련 섹션과 항목은 아래 기준에 따라 필요하지 않으면 생략한다.
- 이론의 시수 편성 요약 표는 `학습 개요` 아래에 `순서 | 주요 학습 개념 | 유형 | 권장 시수 | 비율`로 작성하고, 강의와 실습 소계 및 총 시수를 포함한다. 본문의 각 학습 항목에는 시간만 표시하고 퍼센트는 반복하지 않는다. 항목별 시수는 단원 총 시수 안에서 학습자의 이해도와 실습 진행에 따라 조정할 수 있는 권장 배분임을 표 아래에 명시한다. 확정된 총 시수 안에서 배분하며, 총 시수가 없으면 임의 확정하지 않는다.
- 학습 목표는 수행 가능한 행동을 중심으로 1–2문장으로 쓴다. 도입 내러티브(Hook), 내러티브 및 연결성, 결론의 후속 연결은 학습 흐름이나 요구사항의 필요성을 설명하는 데 도움이 될 때만 작성한다. 형식을 채우기 위해 문제 상황, 이야기, 다음 질문을 억지로 만들지 않는다. 새 개념의 도입 이유나 후속 학습과의 관계가 순서만으로 드러나지 않으면 해당 전환 지점에 연결 설명을 쓴다. 이미 학습 내용에 충분히 설명했다면 중복하지 않는다. 작성할 때도 짧게 설명하고 강사의 대본을 쓰지 않는다.
- 이론의 학습 우선순위는 기본과 심화로만 구분한다. 기본은 공통 학습 범위, 심화는 선택 확장이며 기본 학습의 전제로 두지 않는다. 미션과 프로젝트는 기존의 필수, 기본, 심화 구분을 유지한다. 이때 필수는 기본 범위 안의 최소 달성 요건이며, 심화를 필수 수행의 전제로 두지 않는다.
- 함수명, 파일별 코드 구조, API 필드, 세부 채점표, 분 단위 일정, 검증되지 않은 성능 수치까지 새로 정하지 않는다. 다만 학습 목표나 기존 합의상 꼭 필요한 제약은 유지한다.
- 합의된 내용과 제안을 구분한다. 미확인 장비 기능, 코드 제공 여부, 비용을 확정된 사실로 쓰지 않는다. 집필 단계에서 정할 수 있는 사항은 제작 참고 사항에 짧게 남긴다.

## 워크플로우

### 1. 과정 컨텍스트 수집

사용자에게 커리큘럼, 훈련 대상과 선수 지식, 훈련 목표, 기존 합의 자료를 받는다. 이미 제공한 정보는 다시 묻지 않는다. 자료의 링크나 경로를 받았다면 실제 내용을 읽고 부족한 정보만 질문한다.

과정 목표, 학습자 수준, 선수 단원과 후속 단원의 연결, 필수 기술이나 환경 제약을 파악한다. 자료의 사실과 아직 결정되지 않은 사항을 구분한다. 과거 자료와 최신 입력이 충돌하면 관련 부분을 보여 주고 확인한다.

### 2. 작성 범위와 저장 경로 수집

작성할 교과목과 단원, 각 단원의 유형(이론/미션/프로젝트), 산출물 저장 경로를 사용자에게 받는다. 입력으로 확인되지 않는 단원 구성이나 유형은 임의 확정하지 않는다. 기존 파일을 수정하는 경우 해당 파일도 읽는다. 일괄 수정에서는 현재 작업본과 보관본을 구분하고, 사용자가 지정한 범위만 수정한다.

여러 단원은 단원별 파일로 작성하고, 파일명은 사용자가 정한 규칙이나 대상 폴더의 관례를 따른다. 둘 다 없으면 단원 순서와 제목을 사용한다.

### 3. 작성 전 인터뷰

`$grill-with-docs`를 사용한다. 해당 스킬과 그 스킬이 연결하는 `grilling`, `domain-modeling`의 지침을 읽고 적용한다. Skill 호출 도구가 없는 환경에서는 각 SKILL.md를 직접 읽어 수행한다. 필수 스킬이 없다면 발견 가능한 스킬 경로를 확인하고, 끝내 찾지 못하면 인터뷰와 작성을 중단하고 필요한 스킬을 사용할 수 있도록 안내한다. 사용하지 않은 스킬을 사용했다고 보고하지 않는다.

이 인터뷰의 결정 범위는 교재의 큰 흐름과 필수 요건이다. 이미 자료에 답이 있는 항목은 확인 질문으로 반복하지 않는다. 프로젝트에 질문 방식이 정해져 있으면 따르고, 그렇지 않으면 인터뷰 스킬의 방식을 따른다.

- 이론: 개념의 선정과 순서, 앞 개념에서 다음 개념이 필요한 이유, 실습의 목적과 배치, 다음 단원 연결을 확인한다. 구체적인 실습 소재 선정은 인터뷰의 필수 결정 사항으로 두지 않는다.
- 미션/프로젝트: 선행 학습으로 수행할 수 있는 핵심 요구사항, 학습자가 직접 구현할 범위, 실습에 필요한 코드와 자료, 결과물에서 확인할 역량을 확인한다.
- 요구사항 달성에 필수적인 리소스는 작성 전에 제공 항목, 목적, 제공 범위를 합의한다. 실제 파일 선정이나 제작, 구체적인 구현 방식은 학습 흐름에 영향을 주지 않으면 유보할 수 있다.
- 시수와 학습량: 후속 교과에 필요한 역량, 학습자가 직접 수행할 범위, 시작 코드의 제공 수준을 바탕으로 학습량을 검토한다. 기존 시수를 채우려고 새 내용이나 반복 활동을 추가하지 않는다. 사용자가 단원 간 시수 조정을 허용하면 교과 총 시수 안에서 배분안을 제안하고, 관련 편성 자료의 반영 범위도 확인한다. 기획상 적정성 판단과 실제 소요 시간 검증은 구분한다.
- 용어 합의와 중요한 선택 이유는 `domain-modeling`에 따라 기록하되, 일반적인 작성 메모를 모두 용어집이나 ADR로 만들지 않는다. 용어집과 결정 기록의 위치는 대상 프로젝트의 관례를 따른다.

핵심 미결정 사항이 해소되면 합의 내용과 유보 사항을 짧게 정리하고 사용자의 확인을 받은 뒤 작성한다. 확인 전 침묵을 동의로 해석하지 않는다. 기획 수준에서 필요 없는 세부 설계로 질문을 확장하지 않는다.

### 4. 단원 기획서 초안 작성

유형별 템플릿에 합의한 내용을 채운다. 인터뷰 기록과 검토 이력은 본문에 넣지 않는다.

**이론**

개념의 학습 순서와 실습 배치로 전체 흐름을 드러낸다. 각 항목은 `강의` 또는 `실습` 중 하나의 유형으로 작성하며, 두 유형을 한 항목에 병기하지 않는다. 기본 항목의 제목은 `### 순서. [유형] 개념`으로 쓰고, 심화 항목만 `### 순서. [유형 | 심화] 개념`으로 표시한다. 이론에는 필수 우선순위를 사용하지 않으며, 기존 필수 항목은 학습 내용을 유지한 채 기본으로 분류한다. 요약 표와 본문의 순서, 제목, 유형, 시수를 일치시킨다. 순서만으로 이해하기 어려운 연결은 필요한 만큼 설명한다. `문제 상황 → 필요한 개념 → 적용 또는 실습 → 다음 질문`은 도움이 될 때 활용할 수 있는 예시이며, 모든 항목에 적용하는 필수 구조가 아니다.

강의는 주강사가 설명할 개념, 실습은 수강생이 먼저 해결하고 주강사가 해설할 활동이 드러나게 작성한다. 두 유형을 분리하되 모든 개념을 같은 제목과 시간의 강의–실습 쌍으로 만들지 않는다. 학습 흐름과 내용별 필요에 따라 설명과 적용을 배치한다. 실습에서는 학습자가 배운 개념을 직접 적용하고 확인하게 한다. 구체적인 실습 소재나 완성된 문제를 정할 필요는 없다. 대신 각 실습 항목에 어떤 개념을 적용하거나 어떤 이해를 확인하려는지, 그 목적을 위해 어떤 수행을 요구하는 문제를 구상해야 하는지 집필 지침 수준으로 적는다.

이론 기획서의 실습 학습 항목은 수강생의 문제 해결과 강사 해설을 모두 포함해 한 항목당 1.5시간 이내로 편성한다. 이를 넘으면 수행 단계나 확인할 개념에 따라 나누고, 각 항목에서 결과 확인과 해설을 마친다. 제목에 번호만 붙여 같은 과제를 형식적으로 분할하지 않는다. 이 기준은 미션과 프로젝트의 전체 수행 시수를 제한하는 규칙이 아니다.

학습 몰입도를 위해 강의만 2시간 이상 연속되지 않도록 중간에 실습을 배치한다. 단원 특성상 개념 설명을 이어가는 것이 적절하면 최대 3시간까지 연속 강의를 허용하되, 그 이유를 교재 제작 참고 사항에 짧게 적는다. 시수 편성 요약 표는 실제 학습 순서대로 작성하고, 제목이 다른 항목이라도 실습 없이 이어지는 강의 시수는 합산해 판단한다.

**실습 리소스와 교재 설명**

실습 리소스에는 환경 이미지, 시작 코드, 데이터, 예제 저장소와 의존성 파일 등 교재 실습에 필요한 항목과 용도, 지원 범위를 적는다. 설치와 사용, 복구, 제출 절차 등의 안내는 교재에 포함할 설명으로 구분한다. 준비 주체는 합의된 경우에만 명시하며, 훈련 기관이나 강사 중 한쪽의 책임으로 임의 지정하지 않는다. 제공되는 부분과 학습자가 직접 작성할 부분의 경계는 유지하되, 본문에서는 자료의 역할을 드러내는 이름을 사용해 “제공된”을 반복하지 않는다.

**미션과 프로젝트**

요구사항은 특정 소재에만 묶이지 않는 기술적 수행과 결과로 쓴다. 무엇을 왜 수행해야 하는지, 어디까지 필수인지 드러내되 상세 구현은 학습자와 집필자의 선택으로 남긴다. 소재는 템플릿의 별도 섹션에 적는다.

리소스는 필수 요구사항을 수행하는 데 필요한 코드, 데이터, 환경과 명세를 빠짐없이 포함하고, 지원 범위와 학습자가 직접 구현할 범위를 구별한다. 필요하다면 준비 상태나 미확인 조건을 덧붙이되 코드 자체를 제작하지 않는다. 비용은 필요한 경우에만 근거가 있는 값이나 미확인 상태를 적는다.

평가 중점은 결과물의 어떤 근거를 보고 피드백할지 3–5개로 정리한다. 점수 배점이나 합격선을 새로 만들지 않는다.

### 5. 별도 에이전트 자가 점검

초안을 최종 경로에 저장하기 전에 별도 에이전트에게 검토를 맡긴다. 초안은 전달문이나 임시 경로로 제공한다. 검토자에게 사용자 입력, 관련 원자료, 인터뷰 합의, 선택한 템플릿, 이 스킬을 제공하고 다음을 확인하게 한다.

- 학습자 수준과 목표에 맞으며 선수 학습과 연결되는가?
- 이론의 개념 순서와 학습 흐름이 이해되며, 후속 교과에 필요한 역량에 맞는 학습 범위인가?
- 이론의 우선순위가 기본과 심화로만 구분되며, 제목에는 심화일 때만 우선순위가 표시되는가? 미션과 프로젝트의 필수 구분을 잘못 변경하지 않았는가?
- 이론의 각 학습 항목이 강의 또는 실습 하나의 유형이며, 설명할 개념과 수행할 활동이 구별되는가? 같은 제목과 시간의 쌍이나 시수를 채우기 위한 활동을 기계적으로 반복하지 않았는가?
- 내러티브가 필요한 곳에만 작성되었는가? 형식을 채우기 위한 이야기를 요구하거나, 불필요한 내러티브를 생략했다는 이유로 미완성으로 판단하지 않는다. 새 개념의 도입 이유와 후속 연결이 필요한 전환 지점에서는 설명이 누락되지 않았는지도 확인한다.
- 이론 실습에 문제의 목적과 구성 지침이 담겨 있는가? 구체적인 소재가 없다는 이유만으로 미완성으로 판단하지 않는다.
- 이론의 각 실습 항목이 강사 해설을 포함해 1.5시간 이내인가? 긴 실습은 수행 단계와 확인할 개념에 따라 나뉘며, 각 항목의 결과 확인과 해설 시간이 포함돼 있는가?
- 시간표의 연속 강의가 2시간 미만인가? 2시간 이상이면 단원 특성에 따른 이유가 있고 최대 3시간 이내인가?
- 실습 리소스와 교재에 포함할 안내를 구분했으며, 준비 주체를 임의로 정하지 않았는가? 미션/프로젝트의 필수 요구사항과 리소스가 대응하며 직접 수행 범위가 분명한가?
- 이론 요약 표가 학습 개요 아래에 있고, 본문의 순서, 제목, 유형, 시수와 일치하는가? 표에는 권장 시수와 비율, 소계와 합계를 표시하고 본문 시수에는 시간만 적었는가?
- 학습량과 지원 범위를 고려해 시수를 배분했으며, 실제 소요 시간이 검증된 것처럼 표현하지 않았는가?
- 합의되지 않은 내용을 확정하거나 불필요하게 상세화하지 않았는가?
- 템플릿의 도움 설명과 자리표시자가 제거되고 문체, 약어, 시수 규칙을 지켰는가?
- 여러 단원 사이에 범위 중복, 선수 지식 누락, 모순이 없는가?

검토자는 초안을 직접 수정하지 않고 문제 위치, 근거, 최소 수정안을 반환한다. 작성자는 타당한 지적을 반영한다. 새 교육 범위나 제공 리소스에 관한 결정이 필요하면 사용자 인터뷰로 돌아간다. 별도 에이전트를 사용할 수 없다면 그 제약을 알리고 대체 검토 방식을 사용자와 정한다. 자체 재독을 별도 검토로 보고하지 않는다.

### 6. 최종 저장

검토를 반영한 파일을 사용자 지정 경로에 저장한다. 링크, 시간 합계와 비율, 남은 도움 설명이나 자리표시자, 새 미들닷을 확인한다. 기존 문서 수정 시 관련 없는 내용과 메타데이터를 보존하고, 보관본 등 작업 범위 밖의 파일은 변경하지 않는다.

완료 시 저장한 파일 경로, 검토 수행 여부, 남은 제작 확인사항만 짧게 알린다. 기획서 검토를 실제 코드, 장비 동작이나 학습 소요 시간의 검증으로 표현하지 않는다.
